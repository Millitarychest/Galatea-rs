## System overview

Galatea is a research EDR for Windows. The endpoint product is "galatea" (crate prefix `galatea-`). The central management server is "babel" (crate prefix `babel-`).

Data flow on the endpoint:

- The kernel sensor freezes each new non-allowlisted process. It sends a process-creation event to the agent with the inverted-call IOCTL. The event keys to a `GA_PID`.
- The agent runs its static-analysis pipeline (signatures, Authenticode, ML, heuristics) against a 4 second budget. It sends the allow or block verdict back. It injects the userland hooks DLL into allowed processes.
- The kernel filter streams file telemetry over a minifilter port. The userland hooks DLL emits ETW events about cross-process activity. The agent correlates all channels into its process and file context caches.
- The agent broadcasts detections to the local GUI over named pipes. The agent registers with babel. Babel stores telemetry in SQLite, serves commands to agents, and renders a web console.

Cross-cutting contracts:

- The kernel freeze APC waits 5 s. The agent scan-wait timeout is 4 s. A scan path slower than about 4 s turns verdicts into fail-closed blocks.
- `GA_PID = SHA-1(namespace | pid | image bytes | creation ticks)[0..16]`. The kernel sensor and the userland hooks compute it from byte-identical inputs. One side out of sync breaks the correlation. The break is silent.
- The `#repr(C)` structs in `galatea-shared` cross the kernel boundary without a version marker. Build the drivers and the agent together.
- The scan path is fail-closed: unreadable, missing, or timed-out files block.
